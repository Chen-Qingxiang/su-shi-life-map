# 数据说明

本项目是阅读《苏东坡新传》和理解苏轼生平空间变化的辅助地图，不是严格的历史地理复原或边界考证。

## 当前数据边界

- 苏轼地点坐标使用现代城市或区域的近似点位，主要用于建立阅读时的空间感。
- 苏轼路线连线表示传记时间顺序和主要行迹节点，不代表精确的古道、水路、驿路或实际旅行轨迹。
- Hartwell / CHGIS 派生图层用于提供 1080 年前后历史 GIS 背景。它比纯手绘示意更适合空间参照，但仍属于近似历史 GIS 语境，不应作为严格国界或行政边界结论。
- 主地图的河流层分为东坡相关 OSM 命名河流，以及 HydroRIVERS 三级水网。它们用于现代水系结构阅读；当前项目暂不考证北宋河道变化。
- 山地保留真实地形晕渲 / 地形底图，同时增加 GMBA 主要山系范围轮廓和 OSM 命名山脊线。
- 如果某个地点、年份、行政隶属或人物关系存在不确定性，后续数据应明确记录不确定性，不应为了显示方便而假装精确。

## 稳定 ID

未来数据层之间应通过稳定 ID 关联，而不是依赖显示名称或列表顺序。

- `place_key`：地点稳定键，用于连接苏轼生平地点、历史地名、行政背景、事件、人物和作品。
- `person_id`：人物稳定键，用于连接人物卡片、人物关系、事件、地点和作品。
- `event_id`：事件稳定键，用于连接地点、人物、作品、时间段和章节。
- `work_id`：作品稳定键，用于连接作品、事件、地点、人物和创作背景。

`data/su-shi-life-locations.geojson` 中的 `order` 仍可用于展示顺序和路线阅读顺序，但不应作为长期跨数据层 join key。

## 数据分层原则

不要把未来数据全部塞进一个巨大 GeoJSON 文件。建议保持以下数据层相互独立，再由前端通过稳定 ID 连接：

- 苏轼生平地点：`data/su-shi-life-locations.geojson`
- 历史地点 / 行政语境：未来可新增 `data/historical-places-sushi.geojson`
- 人物：未来可新增 `data/sushi-people.json`
- 人物关系：未来可新增 `data/sushi-relations.json`
- 事件：未来可新增 `data/sushi-events.json`
- 作品：未来可新增独立作品数据文件
- 章节旅程：`data/sushi-journeys.json`
- 旅程节点 / 一次到访：`data/sushi-journey-visits.geojson`
- 旅程路段：`data/sushi-journey-segments.geojson`
- 旅程作品：`data/sushi-journey-works.json`
- 来源说明：未来可新增更细的 source notes 或 citation 数据

这种分层可以让项目逐步扩展到 CHGIS 风格历史地理、CBDB 风格人物资料、事件、作品和时间筛选，而不破坏当前静态 Leaflet 架构。

## 当前知识种子数据层

项目现在包含一组小规模、手工整理的知识 seed data：

- `data/sushi-people.json`：人物基础资料和与苏轼的关系摘要。
- `data/sushi-relations.json`：以苏轼为中心的少量人物关系。
- `data/sushi-events.json`：与现有 `place_key` 连接的传记事件。
- `data/sushi-works.json`：少量与地点 / 事件强相关的作品。

这些数据主要用于验证交互设计和阅读辅助方向。它们不是完整的 CBDB 数据集，也不是最终考证结论。后续扩展时应逐条核对传记、CBDB、可靠二手研究和必要的一手资料，并补充更细的来源说明。

## 章节旅程设计

生平总览地点和章节旅程节点解决的是不同问题，不应混成同一份地点表：

- 生平总览回答“苏轼一生主要在哪些城市生活、任官或贬居”。
- 章节旅程回答“一次具体移动经过哪些阶段、采用什么交通方式、在哪里停留或触发写作”。
- 同一地点可以出现多次 `visit`，例如荆州既是水路终点、度岁停留地，也是陆路北上的起点。
- `segment` 表示两个行程节点之间的移动；当前连线只表示章节顺序，不代表精确航道或驿路。
- 作品优先关联到 `visit_id`；将来若能确认作品产生于某段舟行或陆行途中，也可进一步关联 `segment_id`。

第一版章节旅程为 `nanxing_1059_1060`。它从 [[01 食蓼少年]] 的路线表和诗作索引生成，收录 24 个行程阶段、23 个路段与 76 首苏轼诗作。部分小地名仍待核，因此节点保留 `certainty` 字段，不为了地图显示而假装精确。

76 首作品已加入 `text`、`text_source_url`、`text_source_label`、`text_status` 和 `text_scope`。其中 74 首来自维基文库《东坡全集》，另有 2 首使用诗歌库《苏轼诗全集》补充；正式引用或讨论异文前，仍应逐首与可靠点校本核对。

## 自然地理图层原则

- **河流**是具有真实几何形态的线网，应使用 HydroRIVERS、OpenStreetMap 等真实矢量数据，而不是手绘几个控制点。
- **山地**主要是连续地形表面，不宜用一条“山脉折线”代替；优先使用 DEM 派生的 hillshade、等高线和地形底图。
- **山系轮廓**适合表达“某山系大致覆盖什么范围”；当前使用 GMBA `300 selection` 中与中国有关的 24 个有公认名称的山系。轮廓不是唯一山脊轴线或精确地貌边界。
- **山脊线**表达具体山岭脊部；当前 OSM 命名山脊图层具有真实线形与名称，但不同地区的覆盖完整度不一致。
- **山峰、关隘与峡谷**适合表示为有来源的点或区域，并保留名称与定位可信度。
- **古道与古代河道**属于历史地理对象。本项目当前不开展古河道复原；没有史料或历史 GIS 支持时，不画出看似精确的历史线路。

### 水系详细度

HydroRIVERS 使用 Strahler order 表达河网等级。地图将其拆成三个可叠加开关：

- `水系 1`：8—9 级，大江干流骨架；
- `水系 2`：7 级，主要支流；
- `水系 3`：6 级，区域河网。

当前三个图层分别包含 4,935、8,296 和 19,423 个河段，合计 32,654 段。

HydroRIVERS 数据不提供河流名称。为避免点击任意河段时反复出现没有阅读价值的等级说明，HydroRIVERS 结构线设为不可点击；另以 Natural Earth 1:10m 河流中心线提供 227 条命名河流参照。命名层负责悬停河名、点击简介和外部阅读链接，HydroRIVERS 负责显示更完整的河网结构。无法可靠识别名称的细小河段不强行命名。

更小的 1—5 级河流数量极大，不适合直接装入当前静态 Leaflet 页面。需要更细时，未来应改用矢量瓦片或按当前视窗动态加载，而不是继续扩大单个 GeoJSON。

对应的浏览器 wrapper 由 `scripts/build_data_wrappers.py` 生成，跨层 ID 引用由 `scripts/validate_knowledge_data.py` 校验。

## 人物关系设计方向

人物关系功能不应从全量 force-directed graph 开始。苏轼相关人物数量多、关系类型复杂，如果一次显示大量节点和边，会很快变得不可读。

更适合本项目的长期方向是：

- 地图优先，人物关系服务于地点、时间和阅读章节。
- 点击地点时，显示该地点相关人物、事件、作品和关系说明。
- 使用人物卡片承载人物生卒年、身份、籍贯、与苏轼关系、相关地点和相关事件。
- 使用局部、过滤后的 ego network，而不是展示全量人物网络。
- 后续再加入时间筛选、地点筛选、人物筛选和 place-event-person 联动。

例如点击“黄州”时，未来界面可以围绕黄州时期展示相关人物、事件、作品和关系类型；但这些内容应作为独立数据层逐步加入，而不是直接混入当前地点点位数据。
