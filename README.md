# 苏轼生平行迹地图

一个围绕苏轼传记阅读建立的静态数字人文工具。

它不只回答“苏轼去过哪里”，还把每一章中的时间、空间、人物、事件和作品放在同一阅读范围内。地图用于建立空间感，时间轴用于恢复叙事顺序，人物、事件和作品卡片则负责展开知识关系与原文。

在线页面：

```text
https://chen-qingxiang.github.io/su-shi-life-map/
```

## 当前定位

本项目以《苏东坡新传》的十四章为主要编排骨架，适合：

- 阅读传记时理解苏轼行程的空间变化；
- 按章节查看相关人物、事件与作品；
- 从地图、时间轴、人物或作品之间来回跳转；
- 检查地点可信度、章节来源和作品文本状态；
- 作为后续苏轼年谱、作品编年和人物关系研究的前端工作台。

它不是严格的古道复原或宋代历史地图。地点坐标、路线和历史政区都保留明确的精度说明。

## 已实现功能

### 十四章章节旅程

章节选择器覆盖第 1—14 章。章节切换后，行程、人物、事件和作品使用完全相同的当前范围。

### 地图与时间轴双向联动

- 点击时间轴节点，地图定位并打开对应行程详情；
- 点击地图节点，时间轴同步高亮并滚动到该节点；
- 行程按章节阶段分组；
- 低可信度坐标使用明确的待核标记。

### 章节知识关系

项目采用章节知识关系模型：

```text
章节
├── 行程节点
├── 人物
├── 事件组
├── 作品
└── 来源与可信度
```

当前关系分为人工明确关联、已建档章节事件关联、姓名/字/号文本匹配和程序派生关系。界面会显示关联依据，不把自动匹配伪装成人工考证结果。

### 人物页

人物卡片包括人物简介、与苏轼的关系、本章作用、关联行程、关联事件、关联作品、全书出现章节及来源。项目同时补入了一批此前只存在于行程文字中的人物，如张方平、范镇、王诜、王巩、李常、文同及乌台诗狱相关人物。

### 事件页

“事件”不再只是重复行程列表。行程回答苏轼何时去了哪里；事件则按“章节阶段 + 事件性质”聚合多个节点，并显示进程、人物、作品与出处。

### 作品原文

作品卡片分为四种文本状态：

- **本地校录原文**：正文保存在项目中；
- **外部全文**：有明确的维基文库页面；
- **自动检索原文**：打开卡片时通过维基文库 API 检索；
- **尚无全文**：需要后续补录。

第一章已有大量本地作品文本。此次升级又将《前赤壁赋》《后赤壁赋》《定风波·莫听穿林打叶声》《记承天寺夜游》《寒食雨二首》保存为本地文本。

### 出处与可信度

章节、行程、人物关系和事件组都可以展开“出处与编辑依据”。目前至少区分章节读书笔记来源、坐标可信度、人物关系来源、作品正文状态以及自动匹配或人工关联。后续可继续补入年谱、文集卷次、一手材料与现代研究文献。

### 全局搜索与筛选

搜索范围随当前模式变化：生平总览搜索全书资料；章节旅程只搜索当前章节。可按地点、行程、人物、事件、作品以及可信度和作品文本状态筛选。按 `/` 可直接聚焦搜索框。

### 深链接与引用

页面 URL 会保存模式、章节、标签以及具体地点、行程、人物、事件或作品。详情面板提供“复制引用”，可复制当前标题、来源说明和深链接。

### 历史背景时间提示

仓库目前只有 1080 年 Hartwell/CHGIS 历史区域切片。界面会比较当前章节年代与 1080 年：年代接近时正常显示；相差超过阈值时默认隐藏；用户仍可手动显示并看到年代差说明。

### 手机端

窄屏下地图保持全屏，资料区改为可开关的侧边抽屉。

## 关键加载顺序

```text
基础数据
→ 十四章旅程数据
→ sushi-knowledge.js
→ sushi-local-work-texts.js
→ 基础查询与地图模块
→ 章节适配器
→ journey-context.js
→ knowledge-model.js
→ workbench-hooks.js
→ wikisource-reader.js
→ main.js
→ workbench.js
```

- `sushi-knowledge.js` 补充人物和关系配置；
- `sushi-local-work-texts.js` 把本地原文附加到已加载作品；
- `knowledge-model.js` 建立章节关系；
- `workbench-hooks.js` 捕获最终地图实例；
- `wikisource-reader.js` 包装作品卡片；
- `main.js` 初始化页面；
- `workbench.js` 最后增加时间轴、搜索、深链接和移动端交互。

## 数据原则

- **事实与推定分开**：区分文献明确记载、年月推定、地点推定、现代坐标近似和程序派生关系。
- **稳定 ID**：人物、事件、作品、章节和行程节点不以显示标题作为唯一关联键。
- **派生关系必须可见**：文本匹配只是发现线索的方法，不等于人工考证。
- **原文状态必须可见**：只有正文保存在仓库并经过检查后，才标为本地原文。

## 自动验证

GitHub Actions 会执行：

```bash
python scripts/validate_workbench.py
python scripts/validate_chapters_04_14.py
find src data -name '*.js' -print0 | xargs -0 -n1 node --check
```

主要检查十四章完整性、模块加载顺序、关系状态、每章人物种子、本地名篇、时间轴/搜索/深链接/出处接入和 JavaScript 语法。

## 数据来源与许可

- 历史区域：Hartwell China Historical GIS / CHGIS；
- 在线底图：OpenStreetMap、OpenTopoMap、Esri；
- 自然地理图层：HydroRIVERS、Natural Earth、GMBA、OpenStreetMap；
- 作品公开文本：中文维基文库；
- 章节整理骨架：《苏东坡新传》读书笔记；
- 本仓库原创代码与整理内容见 `LICENSE` 和 `ATTRIBUTION.md`。

## 已知限制

- 1080 年是目前唯一历史区域切片；
- 大量古寺、园亭、驿站和城内空间仍使用范围性坐标；
- 人物索引仍未覆盖章节中出现的全部人物；
- 只有部分重要作品完成本地校录；
- 当前事件组主要由行程节点聚合，后续仍可升级为人工编写的完整事件档案；
- 本项目用于阅读和研究辅助，不应替代正式年谱、文集点校本或历史地理考证成果。

更详细的数据结构见 `docs/knowledge-schema.md`，当前改造清单与完成状态见 `docs/workbench-todo.md`。
